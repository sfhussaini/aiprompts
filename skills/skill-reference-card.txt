Since you value structured templates like **RISCOR**, your `SKILL.md` should act as the **"Source of Truth"** or the **"Operational Specification"** for the AI.

To achieve this, the template needs to shift from being a *description* of the skill to being a *set of instructions* that explicitly maps **Inputs $\rightarrow$ Process (Tools/Assets) $\rightarrow$ Output**.

Here is a professional **SKILL.md Template** designed for AI agents.

***

# 📄 SKILL.md Template

```markdown
---
name: [skill-name]
description: |
  [One sentence explaining the PRIMARY goal of the skill]. 
  Use when the user provides [Required Inputs] to generate [Expected Final Output].
license: MIT
metadata:
  author: [Name/System]
  version: "1.0"
---

## 🎯 Overview

This skill performs **[Skill Category]** to achieve **[Business/Educational Goal]**.

### Capabilities
- **Primary:** [Main function - e.g., Research and structure content].
- **Secondary:** [Supporting function - e.g., File conversion or validation].
- **Output Format:** [e.g., .docx, .json, .md, or a specific folder structure].

### Constraints (When NOT to use)
- [Constraint 1: e.g., If input X is missing].
- [Constraint 2: e.g., If the task is too simple for this workflow].

---

## ⚙️ Operational Workflow

The agent MUST execute these steps **sequentially**. Provide a status update to the user after each phase.

### 1. Validation Phase
- **Check:** Verify [Input A] and [Input B] are present.
- **Action:** If missing, use `ask_question` to gather specifics.

### 2. Research & Gathering Phase
- **Tools:** Use `fetch_web_content` or `search_codebase`.
- **Goal:** Gather [Specific Data Points] and synthesize them into a knowledge base.

### 3. Structuring Phase
- **Logic:** Organize data into [Specific Hierarchy - e.g., Stages $\rightarrow$ Steps].
- **Criteria:** Ensure the flow follows [Specific Framework - e.g., RISCOR or Bloom's Taxonomy].

### 4. Drafting Phase (Asset Integration)
- **Asset:** Read `assets/[template_name].md` using `read_files`.
- **Action:** Populate the template with researched data.
- **Output:** Save as `[filename].md` using the `editor` tool.

### 5. Processing Phase (Script Execution)
- **Script:** Execute `scripts/[script_name].py` via `run_commands`.
- **Command:** `python scripts/[script_name].py [input_path] [output_path]`
- **Validation:** Verify the output file exists using `filesystem__get_file_info`.

## 📤 Output Specification

Return the final result in this JSON structure:

```json

  "result": {
    "primary_output": "absolute/path/to/file",
    "supporting_assets": ["path1", "path2"]
  },
  "metadata": {

    "processing_time": "0ms"

```

---

## 🛠️ Resource Map

| Resource | Path | Purpose |
|----------|------|----------|
| **Template** | `assets/[name].md` | Provides the structural blueprint for the output. |
| **Script** | `scripts/[name].py` | Handles the conversion/processing of the final file. |
| **Docs** | `resources/[name].md` | Reference guide for the agent to ensure quality. |
```

***

### 🔑 Why this works (The "RISCOR" of Skills):

If we apply your **RISCOR** logic to this template:
*   **Role**: The `name` and `description` tell the AI exactly who it is (e.g., "You are a Workshop Builder").
*   **Instruction**: The `Overview` and `Capabilities` sections define the core mission.
*   **Steps**: The `Operational Workflow` provides a step-by-step algorithm (Validation $\rightarrow$ Research $\rightarrow$ Structure $\rightarrow$ Draft $\rightarrow$ Process).
*   **Context**: The `Resource Map` and `Assets` give the AI the environmental context (Where are the scripts? Where is the template?).
*   **Output**: The `Output Specification` ensures the machine-readable result is consistent.
*   **Rules**: The `Constraints` section sets the hard boundaries of when the skill should or should not be used.
