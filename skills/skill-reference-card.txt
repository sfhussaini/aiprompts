# Consolidated Agent Skills Context

Use this as reference when creating, editing, validating, or reasoning about Agent Skills.

## Skill Directory Structure

A skill is a directory containing at minimum `SKILL.md`:

```
skill-name/
├── SKILL.md          # Required: metadata + instructions
├── scripts/          # Optional: executable code
├── references/       # Optional: documentation
├── assets/           # Optional: templates, resources
└── ...               # Any additional files or directories
```

## `SKILL.md` Format

`SKILL.md` = YAML frontmatter + Markdown body.

### Frontmatter Fields

| Field | Required | Constraints |
|---|---|---|
| `name` | Yes | 1–64 chars. Lowercase letters, numbers, hyphens only. Must not start/end with hyphen. No consecutive hyphens. Must match parent directory name. |
| `description` | Yes | 1–1024 chars. Non-empty. Describes what the skill does and when to use it. Include trigger keywords/phrases. |
| `license` | No | License name or reference to bundled license file. Keep short. |
| `compatibility` | No | 1–500 chars if provided. Environment requirements: product, packages, network access, etc. |
| `metadata` | No | Map of string keys to string values. Use unique keys. |
| `allowed-tools` | No | Space-separated string of pre-approved tools. Experimental. |

### Valid `name` Examples

```yaml
name: pdf-processing
name: data-analysis
name: code-review
```

### Invalid `name` Examples

```yaml
name: PDF-Processing   # uppercase not allowed
name: -pdf             # cannot start with hyphen
name: pdf--processing  # consecutive hyphens not allowed
```

### Good `description` Example

```yaml
description: Extracts text and tables from PDF files, fills PDF forms, and merges multiple PDFs. Use when working with PDF documents or when the user mentions PDFs, forms, or document extraction.
```

### Poor `description` Example

```yaml
description: Helps with PDFs.
```

### Optional Field Examples

```yaml
license: Proprietary. LICENSE.txt has complete terms

compatibility: Designed for Claude Code (or similar products)

compatibility: Requires git, docker, jq, and access to the internet

compatibility: Requires Python 3.14+ and uv

metadata:
  author: example-org
  version: "1.0"

allowed-tools: Bash(git:*) Bash(jq:*) Read
```

Most skills do not need `compatibility`.

## Body Content

No format restrictions. Recommended sections:

- Step-by-step instructions
- Examples of inputs and outputs
- Common edge cases

The agent loads the entire `SKILL.md` once the skill is activated.  
Keep main `SKILL.md` under 500 lines. Move detailed reference material to separate files.

## Optional Directories

### `scripts/`

Executable code agents can run. Should be:

- Self-contained or clearly document dependencies
- Include helpful error messages
- Handle edge cases gracefully

Common languages: Python, Bash, JavaScript.

### `references/`

Additional documentation loaded on demand:

- `REFERENCE.md` — detailed technical reference
- `FORMS.md` — form templates or structured data formats
- Domain-specific files: `finance.md`, `legal.md`, etc.

Keep files focused; smaller files reduce context use.

### `assets/`

Static resources:

- Templates
- Images
- Data files

## Progressive Disclosure

1. **Metadata** (~100 tokens): `name` and `description` loaded at startup for all skills.
2. **Instructions** (<5000 tokens recommended): Full `SKILL.md` body loaded when skill is activated.
3. **Resources** (as needed): Files in `scripts/`, `references/`, or `assets/` loaded only when required.

## File References

Use relative paths from the skill root:

```markdown
See [the reference guide](references/REFERENCE.md) for details.

Run the extraction script:
scripts/extract.py
```

Keep references one level deep from `SKILL.md`. Avoid deeply nested reference chains.

## Validation

Use the `skills-ref` reference library:

```bash
skills-ref validate ./my-skill
```

This checks `SKILL.md` frontmatter validity and naming conventions.

# Canonical `SKILL.md` Template

```markdown
---
name: <skill-name>
description: |
  One or two sentences describing what this skill does AND when to use it.
  Include trigger phrases the user would actually type.
license: MIT
metadata:
  author: <your-org>
  version: "1.0"
---

## Overview

This skill performs **[core function]** on **[input type]** for **[target use case]**.

### What this skill does

- **Primary:** [Main capability]
- **Secondary:** [Optional features]
- **Output format:** [JSON, CSV, Markdown, etc.]

### When NOT to use this skill

- If the input is **[edge case 1]** (e.g., empty file)
- For **[related but different task]** (use `skill-name-alternative` instead)

---

## When to Use

Use this skill when:

- The user says: "**[exact trigger phrase 1]**" or "**[exact trigger phrase 2]**"
- The input is of type: **"[input format]"** (e.g., PDF, Markdown, Python file)
- The goal is to: **"[primary objective]"**

---

## Workflow

Follow these steps **in order**:

1. **[Step 1 - Input validation]**
   - [Check that the input file exists and is readable]
   - [Verify the file format matches expected type]

2. **[Step 2 - Core processing]**
   - [Describe main algorithm or procedure]
   - [Mention any tools/libraries used if applicable]

3. **[Step 3 - Output generation]**
   - [Format the result according to the specified output format]
   - [Include metadata (e.g., source file, processing time) in the response]

4. **[Step 4 - Error handling]**
   - [If extraction fails: return a clear error message with suggested fixes]
   - [If input is ambiguous: ask clarifying questions before proceeding]

## Key Placeholders in Template

- `<skill-name>` — must satisfy naming rules and match parent directory
- `<your-org>` — metadata author
- `[core function]`, `[input type]`, `[target use case]` — overview descriptors
- `[Main capability]`, `[Optional features]`, `[output format]` — capability details
- `[edge case 1]`, `[related but different task]` — exclusions
- `[exact trigger phrase 1]`, `[exact trigger phrase 2]` — user phrases
- `[input format]`, `[primary objective]` — activation criteria
- Workflow steps — input validation, core processing, output generation, error handling
- Required fields table — Field / Type / Description / Example
- Output JSON — `status`, `result`, `metadata`, `warnings`, `errors`
