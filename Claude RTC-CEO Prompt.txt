Usage rules:
In iterative sessions, drop constraints already established in prior turns — don't repeat what's already in context
CONTEXT always references existing work to anchor the new task
CONSTRAINTS should be specific and technical, never vague
EXAMPLES should cover edge cases and error scenarios, not just happy paths
INPUT defines the exact data/code to operate on — never leave ambiguous what's being modified
STEPS provides sequential, actionable instructions — each step must be verifiable
